# 指标与公式

实现位置：`src/family_cfo/finance/metrics.py`。每个指标在输出中附带
`formula`、`sources`、`status`（`actual / estimate / assumption / unavailable`）。

| 指标 | 公式 |
| --- | --- |
| 月度收入 | Σ inflow & `txn_type=income` |
| 月度支出 | Σ(`expense`+`fee`+`reversal`) − Σ`refund` |
| 月度结余 | 收入 − 支出 |
| 储蓄率 | 结余 / 收入（收入为 0 → unavailable） |
| 总资产 | 账户资产 + 非账户资产 + 投资市值 |
| 总负债 | 负债余额 + 信用卡欠款 |
| 净资产 | 总资产 − 总负债 |
| 资产负债率 | 总负债 / 总资产 |
| 流动资产比例 | 流动资产 / 总资产（自住房不计） |
| 应急资金月数 | 流动资产 / 近 3 个月平均必要支出 |
| 固定支出比例 | 必要支出 / 总支出 |
| 债务负担率 | Σ 月供 / 近 3 个月平均月收入 |
| 投资配置 | 各类型市值 / 投资总市值 |
| 年度净资产变化 | 当前净资产 − 12 个月前快照 |
| 目标完成率 | Σ min(当前, 目标) / Σ 目标 |

## 投资收益

- 买入：`成本 += 成交额 + 手续费`，`数量 += 买入数量`
- 卖出：`已实现 += 卖出净额 − 卖出数量 × 平均成本`，成本与数量同步减少
- 分红：单独计入现金流，不冲减成本
- 未实现：`用户市值 − 剩余成本`；无市值时 `null`，绝不使用“实时行情”

## 结算双算校验

`settle` 会用 SQL 聚合与 Python 汇总分别计算收入/支出，二者必须相等，否则 `amount_validation`
阻塞关账。这是防止统计逻辑漂移的最后一道闸门。

## 不可用状态

以下情况返回 `unavailable` 而不是 0：

- 未录入任何账户余额/资产 → 总资产、净资产；
- 未录入负债 → 总负债；
- 无收入 → 储蓄率、债务负担率；
- 无支出 → 应急资金、固定支出比例；
- 无 12 个月前快照 → 年度净资产变化；
- 无目标 → 目标完成率。

## 健康诊断阈值

| 指标 | 良好 | 关注 | 风险 |
| --- | --- | --- | --- |
| 应急资金覆盖 | ≥ 6 个月 | ≥ 3 个月 | < 3 个月 |
| 储蓄率 | ≥ 20% | ≥ 5% | < 5% |
| 资产负债率 | ≤ 30% | ≤ 50% | > 50% |
| 债务负担率 | ≤ 30% | ≤ 50% | > 50% |
| 流动资产比例 | ≥ 20% | ≥ 10% | < 10% |
| 单一持仓集中度 | ≤ 50% | ≤ 70% | > 70% |

权重：应急 25、储蓄 20、负债率 20、债务负担 15、流动性 10、集中度 10。
`unavailable` 的项目不计分并重新归一；全部不可用时评分为 `null`，等级“数据不足”。
待确认交易单列为“关注”，不改变评分。
